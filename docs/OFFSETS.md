## 如何定位

本页以 Windows x64 的 `Weixin.dll` 为基准。先核对版本和上面的 SHA-256，再使用目标微信进程实际加载的模块基址；不是 `Weixin.exe`、本仓库 DLL 的基址，也不是 PE 头里的首选 ImageBase。

`运行时地址 VA = 当前进程中 Weixin.dll 的加载基址 + RVA`

例如，假设模块基址为 `0x00007FFB00000000`，公共提交 RVA 为 `0x017B4720`，则地址为 `0x00007FFB017B4720`。这是计算示例，不是固定地址。ASLR 会使不同电脑、不同启动的基址变化；同一份 DLL 的 RVA 不因此变化。重启后重新取基址，切换账号后重新获取业务对象，不能复用之前的对象指针。

在 IDA / Ghidra 中，跳转到分析数据库的 ImageBase 加 RVA；在调试器中，跳转到目标进程的 `Weixin.dll` 模块基址加 RVA。函数项应落在代码区，虚表项应落在数据区。模块版本相同但 SHA-256 不同，不视为适配同一份二进制。

RVA 也不是十六进制编辑器里的文件偏移。位于某节的原始数据范围内时：`文件偏移 = RVA - 节 VirtualAddress + 节 PointerToRawData`；只有内存空间、没有原始数据的区域不能这样读取文件字节。[PE 地址定义](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)。

**定位到函数不等于能直接调用。** 还需要正确的参数、对象布局、业务线程、引用计数及当前登录会话。本页不是完整调用 ABI。一次本机提交成功也不等于对方设备已经收到。

下表计算方式是 `该对象的起始指针 + 字段偏移`，不是 `Weixin.dll 基址 + 字段偏移`。不同类型不能混用。

文本类型 `1`、语音类型 `34`、引用类型 `0x3900000031` 是消息类型值，不是偏移。

工作台中的搜索、导出、AI 分析等功能不一定对应独立的微信原生入口，本表不为它们虚构偏移。
